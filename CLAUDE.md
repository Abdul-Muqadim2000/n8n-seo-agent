# n8n_devaicon — SEO Agent (n8n)

Enterprise SEO automation built as n8n workflows: keyword research, keyword verdicts, long-form content with QA, technical site audits, full SEO reports, AI-visibility checks. Everything lives in `n8n/seo-agent/`; the stack runs locally with Docker Compose from `n8n/`.

## Read first
- `n8n/seo-agent/HANDOVER.md` — current state, how to use every mode (with API bodies), what is verified live, open items for the user. Start here.
- `n8n/seo-agent/REVIEW.md` — findings, every change (per feature: §3c ladder, §3d tracking, §3e cadence + blog package, §3f Search Console audit, §3g notices + check-in, §3h E-E-A-T and page types, §3i growth monitors), the live-test log (section 5c), go-live checklist, roadmap.
- `n8n/seo-agent/LADDER_FEATURE_SPEC.md` — keyword ladder (choice step, ladder plan, rank tracker, "rank my site for this keyword" mode).
- `n8n/seo-agent/MONITORS_FEATURE_SPEC.md` — growth monitors (v4.5): AI Visibility Tracker, Backlink Monitor, Audit Scheduler; audit diff, fix pack, entity check; costs and decisions.
- `n8n/seo-agent/TRACKING_FEATURE_SPEC.md` — site tracking (Search Console, GA4, Google Trends, live checks; "Track my site" mode, Site Tracker workflow).
- `n8n/seo-agent/CHANGES_v3_to_v4.md` — generated list of patches applied by the build.
- `n8n/seo-agent/docs/SEO_Agent_v4.6_Developer_Guide.pdf` (+ .html) — developer guide (212 pages): all 14 workflows and 658 nodes explained, schedules, build/test/deploy, config, all 21 Data Tables, API contract (every mode and callback stage), the 2026-10-01 system test and the 2026-10-02 live runs with per-run node traces; regenerate with `python3 capture_runs.py <execution ids>` (traces + published state into `docs/runs/`) then `python3 build_docs.py --pdf` (renders through Gotenberg inside the n8n container).

## Working rules
- Edit prompts/code in `v5/`, wiring in `build_v4.py`; then `cd n8n/seo-agent && python3 build_v4.py` and **check the exit code** (patches are anchored on exact text and assert; don't pipe the build to `tail` without `pipefail`).
- Run the harness after every change (copy `harness/` into the container as a fresh dir, chown to `node`, run `scenarios_v5.js`).
- Import with `docker exec n8n-n8n-1 n8n import:workflow --input=/tmp/<file>.json --projectId=wo1WpMiHjdduGvfl` (upserts by id; import deactivates, so re-activate through the n8n API `POST /api/v1/workflows/<id>/activate`).
- Sub-workflows called through Execute Workflow must be *published* in n8n 2.x (an unpublished one fails with "Workflow is not active"). Script-created Webhook nodes need a `webhookId`; Form "completion" nodes throw in API-started runs (guard with `via_webhook`); n8n forbids Respond-to-Webhook nodes downstream of a Form Trigger (hence the separate API workflow).
- n8n keeps HTTP-node binaries on disk: Code nodes must use `await this.helpers.getBinaryDataBuffer(i, prop)` to get bytes.
- HTTP Request nodes with `responseFormat: text` (+ full response) return the body under `data`, not `body`; read `r.body ?? r.data`. Crawls report `www.` URLs while canonicals and sitemaps may use the bare host: compare URLs host-agnostically.
- The n8n Code sandbox has **no `URL` constructor** (and a try/catch around it hides the failure): parse hosts with a regex. The harness shadows `URL` so such code fails offline. Data Table *create* nodes output the table object, not the input item: read upstream nodes explicitly after them.
- An n8n **AI Agent node outputs only `{output}`**: a prompt in a node whose input is an agent's output must read context with `$('Node').first().json`, never `$json` (the critic was blind to the brief until 2026-10-02). Data Table upsert/insert nodes auto-map every input field: feed them exactly the table columns.
- Anthropic node: thinking tokens count against `maxTokensToSample`; set `streaming: true` above ~21k tokens (SDK 10-minute rule); streaming calls report no token usage.
- **Secrets and client settings live in `n8n/.env`** (`SEO_*`, template `n8n/.env.seo.example`). After editing it run `python3 seo-agent/apply_env.py`: rebuilds with the settings (`SEO_BRAND`, `SEO_MAIL_FROM`, `SEO_OPS_EMAIL`, `SEO_GOOGLE_SA_EMAIL` are baked in at build time), writes the credential records from `.env` (`sync_credentials.py`, literal values, fixed ids, empty variables skipped), imports, publishes, restarts. `$env` is blocked in nodes on this instance and never works for trigger auth, so do not use `{{ $env }}` in workflows or credentials. Never export or print credentials from n8n (the auto-mode classifier blocks it too). Credentials live in n8n under fixed ids (`SEOcredDataForSE`, `SEOcredJinaReade`, `SEOcredPageSpeed`, `SEOcredAnthropic`, `SEOcredFormLogin`, `SEOcredApiHeader`, `SEOcredSmtpGmail`, `SEOcredGoogleSvc` = Google service account `devai-seo@techand-site.iam.gserviceaccount.com` for Search Console + GA4, real key installed 2026-10-02 — the user pasted it in chat, so rotate it after testing); `SEOcredImapGmail` = Gmail IMAP for the Console Alerts watcher, **not created yet** (needs the Gmail App Password; same value as the SMTP credential)); the API caller secret is credential "SEO API Key"; `SEOcredApiTest01` is the Test Runner key (value in no file; reset it from the UI when needed). The SMTP credential needs a Google App Password (placeholder until provided).
- **Send Email 2.1** attaches files only through `options.fileAttachments` (comma-separated binary keys); `attachments` embeds inline, `attachmentsUi` is ignored. Every e-mail node retries 3× (transient `EAI_AGAIN` DNS failures happen).
- DataForSEO from the Mac fails TLS (corporate proxy): probe APIs from inside the n8n container (node fetch, credentials passed by env var, never printed). `backlinks/domain_intersection`: `intersection_mode: partial`, the linking domain is `target`. Google Business Profile lookups by name can match other companies: accept a listing only with the site's website or phone.
- Inline `//` comments inside one-line JS edits swallow the rest of the line (`}]`, `const a = …`): put comments at the end of a statement. A short domain label (e.g. "techand") can match other companies in AI answers / mentions: set `brand_names` through Site Admin `monitors`.
- The n8n public API activates a workflow (`POST /api/v1/workflows/<id>/activate`) without a restart (webhooks register within seconds) and manages Data Table rows (`/api/v1/data-tables/<id>/rows`, `…/rows/delete?filter=`).
- `.env` values contain spaces: do not `source` it in a shell; read it with `env_settings.load_env()` (Python). `build_docs.py --pdf` renders the guide through Gotenberg from inside the n8n container (without `--pdf` it writes only the HTML).
- Spend: `ai_budget_usd` / `ai_budget_period` in *Normalize Input* CONFIG is an estimate-based guard ($6 per day since 2026-10-02, set in `build_v4.py`); the Anthropic Console workspace limit is the real cap. Run reports for people outside the build: `python3 run_report.py --exec <ladder id> --exec <page id>` → styled HTML in `docs/run-reports/` (stages, outputs, page preview, delivered documents, cost; reads n8n through the API). DataForSEO balance was $32.6 on 2026-10-01.
