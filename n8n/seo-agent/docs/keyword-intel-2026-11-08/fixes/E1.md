# KI E1: the keyword-intelligence kit `KI` (2026-11-08, branch `ki/e1`)

Scope: CONTRACTS.md section 8 "E1". The pure kit `v5/code/_ki.js`, its harness scenario `harness/scenarios_ki.js` (KI1-KI25, wired into
`scenarios_v5.js` after KIW0), the labelled sets `harness/accuracy/ki_domains.json` / `ki_stage.json`, the parity fixture extension.
Nothing deployed, pushed, or paid for; no production access. No workflow inlines the kit yet (E2 does), so every generated workflow is
byte-identical to `ki/integration` (the build rewrote no generated file).

## 1. How it is inlined (for E2)

`KI` calls the existing kits instead of copying them. A node that inlines `_ki.js` must inline, before it, in this order:
`_fit_gate.js` (required: `fitGate`, `fitMarket`, `fitEvidence`), `_competitors.js` (required: `CMP`), and optionally `_kw_inputs.js`
(`KWI.shapeOf`) and `_site_model.js` (`SM.matchPage`, used by `KI.pageAction` when a site model is passed). Without the fit gate,
`KI.gate` fails closed (every keyword `fail`). `var KI = (typeof KI === 'object' && KI.VERSION === 'ki-1') ? KI : ...` lets two inlined
copies share one. Pure: no clock (`cfg.now` / `client.now` when a date is wanted), no random, no URL constructor, no table or network
access, ASCII only (checked by KI1).

**gate_lint (for E2 / the orchestrator)**: the `seo_ki_keywords` pair should be `kit: '_ki.js'`, `write: 'KI.gate('`, `read: 'KI.readable('`.
The kit itself calls `fitGate(`, so a pair keyed on `fitGate(` would count a node as gated merely for inlining `_ki.js`; gate_lint
strips the kit text first only for the kit named in the pair.

## 2. API as built (CONTRACTS section 6, plus helpers)

| Function | Returns / notes |
|---|---|
| `KI.VERSION` | `'ki-1'` |
| `KI.CONFIG`, `KI.cfg(over)` | every number (section 3); `cfg` deep-merges a run's `config_json` (object or JSON string; arrays replace) |
| `KI.norm(kw)` / `KI.key(kw)` | shown form / close-variant key (stop words out, plurals folded, `e invoicing` = `einvoicing`, `&` = `and`, word order ignored) |
| `KI.services(v)` | the site's services as a LIST of phrases: arrays kept, JSON arrays parsed, strings split on lines / `;` / `|` / bullets, on commas only when every piece is a short phrase (R3 #4: a sentence is never cut) |
| `KI.validHost`, `KI.reg`, `KI.hostOf(item)`, `KI.urlKey(item)` | host recovery rules: `domain: null` skipped; a Google redirect still on google.com = unknown; `url_exact:false` keyed by host + path tokens (same key as the exact url of the same page); `url_partial:true` has no key (host only) |
| `KI.classifyDomain(host, ctx)` | `{ class, basis, confidence, reasons, valid, host, reg, store, needs_review, reject?, topic_sim?, geo_match? }`. `store:false` + `reject` in `fragment` / `search_engine` / `own_site` (never stored). Order: valid host -> own site -> `user` class -> principal (vendor of a product named in the services: Microsoft / Dynamics, Open edX, Odoo, SAP, ...) -> search engine -> government / regulators -> job board -> directory (Clutch, GoodFirms, G2, DesignRush, Capterra, ...) -> media -> platform / other vendors -> CMP host kinds -> declared -> page signals (`ctx.appearances`, `ctx.pages`, untrusted) -> `llm` (only when `ctx.llm` is passed) -> topic / market rule. Confidence < 0.6 = needs review |
| `KI.pageType(item, ctx?)` | `provider` `vendor` `list` `directory` `guide` `forum` `job_board` `government` `news` `video` `other`; null when the host is unknown |
| `KI.top10(items, ctx, cfg)` | the stored `top10_json` shape `[{ url, host, type, pos, exact }]` (no-host items skipped) |
| `KI.stage(top10, keyword, labsIntent, ctx?)` | `{ stage, intent, confidence, evidence, shares, counts, read, needs_review, by }`; evidence like "10 results read: 7 company service pages, 2 directories, 1 list -> people looking to hire" |
| `KI.gate(keyword, ctx)` | `{ gate: pass/fail, reason, text, detail }`; reasons `other_market`, `career`, `other_brand`, `government`, `portal`, `navigational`, `own_brand`, `off_topic`, `too_broad`, `empty`, `avoid` (a stored AVOID, `ctx.avoid`); `low_fit` is applied by `score` / `verdict` |
| `KI.fit(keyword, ctx, top10?)` | `{ fit, low, high, basis, unknown, geo, detail }`: `fitEvidence` share (x 0.75, + 0.25 of titles in topic when 3+ titles are given) x place match (in market 1, no place 0.9, outside 0) |
| `KI.mergeCandidates(lists)` | rows with every source, `families` (independent evidence: the three Labs endpoints are ONE family, tracked / ladder / seed none), provider volume / CPC / KD with basis, GSC fields from `gsc` only; sorted by `kw_key` |
| `KI.prescore(row, cfg)` | 0..100, fit inside (R1 #4), gated 0 |
| `KI.cluster(rows, cfg)` | rows + `cluster_id` (`c_<hash of head key>`), `is_head`, `cluster_size`, `cluster_demand`, `hub_id`, `shared_with_head`, `borderline`, `compared` |
| `KI.demand(cluster, cfg)` | `{ demand, low, high, clicks, basis, floor, note }` |
| `KI.win(row, site, cfg)` | `{ win, low, high, strength, strength_known, existing_rank, topical, weak_spots, position, position_basis, parts }` |
| `KI.value(row, site, cfg)`, `KI.gap(row, chosen, cfg)` | Value and Gap factors (`KI.gap` is the factor; `KI.gaps` the rows) |
| `KI.score(row, cfg)` | `{ score, low, high, mid, factors:{ gate, fit, stageW, demand, win, value, gap }, low_confidence, reason }` (row factors may be numbers or the objects above) |
| `KI.verdict(row, cfg)` | `go` / `months` / `hard` / `gated` from Win (and gate, Fit < 0.35) |
| `KI.sizeTag(client, comp, cfg)` | `peer` / `leader` / `smaller` / `out_of_reach` / `unknown` |
| `KI.scoreCompetitors(domains, seeds, cfg)` | rows in `seo_ki_competitors` shape (JSON fields as arrays; E2 stringifies): only direct / adjacent scored, with 3+ seeds a scored row needs 2 seeds seen; `cfg.ctx` = the classify ctx, `cfg.client` = `{ keywords, refdomains }` |
| `KI.striking(row, site, cfg)` | one definition: GSC 8-20 with >= 100 impressions / 28 d (>= 30 when the site has < 5,000) |
| `KI.pageAction(cluster, site, cfg)` | `{ action: new/refresh/list/none, page_url, reason, list_hosts, cannibal }`: list when >= 50% lists / directories (page kept in `page_url`), refresh when the site ranks or a page matches (`SM.matchPage` with a model, else title / slug tokens), else new; 2 ranking pages = cannibalisation |
| `KI.gaps(client, chosen, rows, extra, cfg)` | `seo_ki_gaps` rows as stored (JSON columns as strings, `sample of N of M`, deterministic `gap_id`) |
| `KI.plan(clusters, gaps, cfg)` | <= 10 `{ action_id, kind, title, why, target, credits, cluster_id | gap_id, ev }`, ASCII, ranked by expected value |
| `KI.readable(row, ctx)` | fails closed: true only when `ctx.killed === false` and `ctx.mode === 'on'` and the row passes (keyword: stored gate pass, and `KI.gate` again when `ctx.fit` is given; competitor: valid host, not a search engine / own site / dismissed) |
| `KI.label(basis, source, fetched_at)` | `{ basis, text, date }`: "measured on <date>", "estimate from <source> on <date>", "our estimate", "AI judgement", else "not available" |

## 4. Accuracy (labelled sets from the production read, hold-out = every third case, fixed before tuning)

| Set | Cases | Train | Hold-out |
|---|---|---|---|
| `ki_domains.json` (classes + reject) | 100 (techand.ai 55, devaicon.com 45): platform 33, reject 26 (fragments, google.com, the site), direct 17, directory 10, principal 5, media 3, publisher list 2, government 2, adjacent 1, job board 1 | 65 / 67 (97.0%) | **32 / 33 (97.0%)** |
| `ki_stage.json` stage | 86 keywords (38 with a stored results page): hire 26, compare 24, solution 23, info 10, problem 3 | 56 / 58 (96.6%) | **27 / 28 (96.4%)** |
| `ki_stage.json` intent | same | 56 / 58 | **26 / 28 (92.9%)** |

KI23 fails the harness under 90% on any of the three hold-outs. Remaining misses: domains `bayzat.com` (HOLD) and `halsimplify.com`
(list publishers read as direct once their untyped appearances outnumber the typed list one), `focussoftnet.com` (direct read as adjacent:
the seed's own topic share is 33%); stage `microsoft dynamics erp` (HOLD, intent informational vs commercial), `crm for customers` (HOLD,
solution vs info: no results page passed), `adaptive software development` (a methodology the words cannot tell), `pdf vs e-invoice uae`
("vs" reads as a comparison; the labeller judged it problem-aware).

How the sets were built (`gen_sets.py`, run from the scratchpad, not committed): the private dump `~/seo-agent-secrets/keyword-intel-2026-11-08/data`
was read only; 16 stored top-10 readings (`seo_rank_history.snapshot_json`) were typed by hand from their titles and addresses, 51 stored
page-type counts came from the keyword reports and checks, 4 search-engine and AI-target competitor strings from `seo_ai_targets`. Only
domains and keywords already present in the public repo (git grep) were written; titles, page addresses and personal data are not in
the files (a case carries host, client, class and `appearances: [{keyword, position, type}]`). Labelling rule for businesses: `direct` =
sells the client's service category with no contrary market evidence, `adjacent` = another market's ccTLD or a partly overlapping
service. Disclosure: the known host lists in the kit (directories, media, platforms, regulators) are general knowledge and include some
labelled domains by construction; the stage rules were tuned on train errors only.

## 6. Deviations from the contract, and why

1. **CMP is not changed.** `KI.classifyDomain` wraps `CMP.kindOfHost` and maps its kinds to the 9 classes, adding principals, more
   directories, trade media, regulators and other vendors in KI only, so every existing caller of CMP answers exactly as before. One CMP
   rule is overridden inside KI only: its platform list matches a vendor word before ANY suffix (`dynamics.ae` = DBS, a UAE partner), so a
   country-only domain is a business unless it is a principal.
2. **Extra exports** beyond section 6 (`cfg`, `services`, `validHost`, `reg`, `hostOf`, `urlKey`, `top10`, `gate`, `fit`, `families`,
   `value`, `gap`, `striking`, `GATE_TEXT`, `VERDICT_WORDS`, `CLASS_IDS`, `PAGE_TYPES`, `ascii`, `hash`) and optional trailing
   parameters (`pageType(item, ctx)`, `stage(..., ctx)`, `gaps(..., cfg)`, `sizeTag(..., cfg)`): E2 needs them and none changes a listed
   signature.
3. **Gate reasons** are wider than the four named: everything the shared fit gate refuses, plus `avoid` (a stored AVOID verdict; R3 F7)
   and `low_fit` (Fit < 0.35, R4 6.4). "what is a crm company" and "erp system" are gated `too_broad` for techand by the shared gate.
4. **`KI.gaps` returns stored rows** (JSON columns as strings), `KI.scoreCompetitors` returns arrays for `reasons` / `evidence` (E2
   stringifies `reasons_json` / `evidence_json`, adds site / market / dates / `profile_json`).
5. **`KI.readable` needs `ctx.killed === false` explicitly** (an absent kill-switch reading is "killed", as CONTRACTS section 1 says).
6. **Labelled sets**: 38 of the 86 stage cases have a stored results page (production holds 16 readings with titles, many keywords not
   in the repo); the other 48 are keywords quoted in the repo docs (R3 Search Console queries, R4 examples) judged on their words. The
   `adjacent` class has one case: the stored data shows almost no foreign-market rivals.
7. Parity fixture gained E1 keys (`score_weights`, `win_weights`, `comp_weights`, `cluster`, `gate_reasons`, `score_cases`); the app test
   reads only the W0 keys and still passes.
