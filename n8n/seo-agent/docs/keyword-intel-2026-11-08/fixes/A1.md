## What was built
- **Routes** `app/server/src/routes/ki.ts` (registered in `app.ts`), all under `/api/orgs/:orgId/sites/:siteId/ki`: `GET ''` (overview with
  the hero's counts, credits, last runs), `GET competitors` + `.csv`, `PATCH competitors/:compDomain`, `GET keywords` + `.csv`, `GET gaps` +
  `.csv`, `PATCH gaps/:gapId`, `POST questions/approve`, `POST plan/:actionId/start` (501), `PATCH mode` (platform admins only).
  Viewer reads; member changes statuses; admin approves questions (as the AI panel manager); platform admin switches the mode (member of the
  company or not, as the AI ranking trial). Verified website, site of the company (siteAccess). Rate limits: lists 240/min, CSV 30/10 min,
  writes 60/10 min, approve 30/10 min, mode 20/10 min.
- **Visibility** (`services/kiData.ts` `kiState` / `requireKiVisible`): On, or Trial + platform admin, and the kill switch off; every data
  route 404 otherwise. The kill switch is read only for Trial / On websites (an Off website reads nothing more); a read error = killed.
  A non-admin reads Trial as `off` in the overview.
- **Reads**: the four KI tables through `siteRows` (TABLES keys from W0), filtered by domain in the n8n request AND on the returned rows
  (a leaked row of another domain is never mapped; tested), JSON columns parsed, mapped once to the camelCase views, server-side filter /
  sort / page (page size max 200), market = asked, else the newest delivered run's, else the commonest.
- **Cache**: `services/ki.ts` `kiCache` (60 s per website), emptied by a KI callback (`ingestCallback`), every status PATCH, the mode
  switch and the site delete. The n8n client's own 60 s read cache sits under it.
- **CSV**: streamed (`Readable.from`, chunks of 500 rows), every cell through the existing `csvCell` (leading `= + - @`, tab, CR, and after
  leading whitespace, neutralised), basis label + `fetched_at` columns; file names `keywords-<domain>-<date>.csv`.
- **Writes**: `ki_competitor` / `ki_gap` through Site Admin per CONTRACTS §5 (`{domain, site_id, request_id, market, comp_domain, status}` /
  `{gap_id, status}`); the app refuses the (max+1)th chosen competitor with **409 `ki_max_competitors`** before calling the engine (and maps
  an engine refusal mentioning the limit to the same 409); `ki_max_competitors` read from the monitors row (default 5).
- **Questions**: `ai_prompts` add (the panel manager's path, same body shape), only as many as the panel has room for (panel size minus
  the owner's own live questions), the rest `panel_full`; also `not_found`, `gated`, `not_a_question`, `already_on_panel`, `duplicate`.
- **Mode switch**: Site Admin `monitors` with `{ki_mode}` only, then a fresh read back; 502 when the engine did not keep it.
- **Callbacks**: `summaries.ts` cases for `ki_competitors` / `ki_research` (+ started): `status`, `partial` + `missing` sections, `reason`,
  `trial`, `market`, counts. `finishedStatus` reads `partial` as finished for the two KI final stages only (delivered, says what is
  missing). Refused / failed = run failed and not charged (W0's `kiNoResultOf`). **Trial**: delivery hold `trial` (new `HoldCode`), no
  webhook event, hidden from non-admins in the reports list / report / run detail / share creation / API v1.
- **Credits**: `GET .../ki` quotes with the run path's own `estimateCost` + `quoteCredits` (never another number); cost sync is the generic
  one (ledger settle tied by request / execution id, capped at the quote, failed refunded), so a repeat inside the TTL is quoted the same
  and charged what the ledger settles (0 when reused).
- **Recommendations / Needs you**: `kiForRecs` is null unless On and not killed; `ki:competitors` ("Choose your competitors", no choice by
  a person yet) and `ki:quick-wins` ("N quick wins found"); rule scores in `queue.ts`; Needs-you kind **`ki`** (shared type,
  `GUIDE_FOR_NEEDS_YOU_KIND` placeholder `choose-first-keyword`, `KIND_RANK` 11.5, web `KIND_ICON` one line). Guide ids agreed in
  `ki-api.ts` `KI_GUIDE_IDS`: `ki-choose-competitors`, `ki-read-keyword-research`, `ki-verdicts` (A2 writes and maps them).
- **API v1 / MCP**: `get_table` and `GET /api/v1/websites/:id/tables/:table` take `ki_competitors`, `ki_keywords`, `ki_gaps`, `ki_runs`,
  read-only, for an On website of the key's company only (anything else = "Unknown table"); not added to the scheduled warehouse exports
  (`EXPORT_TABLES` unchanged, so Off sites' exports stay identical).
- **Site delete**: verified the app's delete path calls Site Admin `delete` (`stopInEngine`, also used by company delete); added
  `clearKiInEngine` (the four tables by domain, like the AI / index clears) for an engine without E2's step.
- **Audit**: `site.ki_competitor`, `site.ki_gap`, `site.ki_questions_approved`, `site.ki_mode` in `AUDIT_ACTIONS`.
- `app/API.md`: section "Keyword intelligence", MCP tool list line.

## Deviations, and why
1. **Questions approve needs admin**, not member: the AI panel manager (Site Admin `ai_prompts`) is admin-only today; a member adding to
   the paid weekly panel would bypass that. Contract §7 named no role.
2. **No market-consistency warning** (`checkWrite('ai_questions')`) on approve: the KI rows are in the website's own main market (E2
   refuses others with `market_mismatch`), so the warning cannot fire; the market is copied from the row.
3. **Client-portal roles get 403** on every KI route (viewer minimum): the pages are not in `PORTAL_SITE_PAGES` yet.
4. **Trial reports hidden** beyond the contract's words (list, detail, run detail, share, API v1, events, delivery): "results for
   platform admins only" would otherwise leak through the company's reports list and e-mails.
5. **`GET .../ki` answers 200 for every website** (not 404): the nav needs it to decide; for a non-admin it carries no data and reads
   Trial as off, so existence is not leaked.
6. **Needs-you kind `ki` mapped to `choose-first-keyword`** until A2's guides exist (`GuideId` is derived from the catalogue, so the KI ids
   cannot be referenced before they are written). Items and recommendations carry the agreed ids via `KI_RECOMMENDATION_GUIDES` /
   `KI_NEEDS_YOU_GUIDES`.
7. **Partial reports are delivered** (finished status), with `partial` / `missing` in the summary; refused / failed are held.
8. **API v1 KI tables are On only**, never Trial, even for a session of a platform admin.
