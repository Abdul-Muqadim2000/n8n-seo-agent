## 2. For other owners (not changed here)

- **FX-A / P4 (engine verification of RC-3).** ARL.verify reads `a.client_url` on the stored action and then looks the URL up in the source graph. The app now writes `client_url` on the `seo_ai_rank_actions` row and a `seo_ai_rank_sources` row (`names_client: true`, `source_from: 'client'`, `last_seen` / `checked_at` now). To close it: add `('client_url', 'string')` to `AI_RANK_ACTIONS_COLS` in `ladder_common.py` (then `sync_tables.py`), make the actions upsert keep it (write it from the stored row, never blank it), and keep `source_from: 'client'` rows in `ARD.sources` beyond `sources_max` (they have influence 0 and can be cut today). Until the column exists, the app's write fails and is logged at warn; the app's own check still decides the step.
- **FX-A (L07).** Its ref is `{ prompt_id }`, so `verify` looks for an empty URL. The report step now shows the page (from the chosen action's `page_url`), but the engine's verification needs the page URL in `ref` or a stored column.
- **AE5 / AP tests.** The callback's `ai_rank` is v 2: `client` replaces `memo` / `cost` / `compare`. The raw memo stays in `seo_ai_rank_runs.memo_json` (platform admins, trial view, `ai_rank_shadow_report.py`).
