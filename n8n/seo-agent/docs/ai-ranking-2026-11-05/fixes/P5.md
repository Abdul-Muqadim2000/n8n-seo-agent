# P5: Integrations (AIR, 2026-11-06)

This is branch `air/p5`, based on the wave-1 integration head `29af3f00`. Nothing was pushed or deployed, no paid call was made, and production was
not touched. Paths are relative to `n8n/seo-agent/`.

## 1. What is built

Everything P5 adds runs **only for a website in mode `on`** (`AIRF.mayPay`), and each paid or keyed read also needs its own switch:

| Read | Provider | Switch on top of `on` | How often | Cost |
|---|---|---|---|---|
| Pages AI answers cite for the site's topic (`top_mentioned_pages`) and the client's own mention count (`target_metrics`) | DataForSEO LLM Mentions | `ai_rank_mentions` | once a calendar month (marker `AIRF.mentionsKey(site, 'yyyy-mm')`) | 2 tasks |
| Fan-out results pages, Google and Bing, depth 10, in the site's market | DataForSEO SERP | `ai_rank_fanout_n` > 0 (= paid reads a week, both engines together) | weekly | $0.002 a read |
| Claude retrieval proxy: Brave web results for the same searches | Brave Search | `ai_rank_brave` AND the key `SEO_BRAVE_API_KEY` at build time | at most 10 searches a week | ~$0.005 a search |
| Bing positions per query and page, crawl issues, crawl stats | Bing Webmaster (existing key) | the site is in this account's Bing list | weekly, at most 7 calls | free |
| Is the site in the latest Common Crawl, how many captures | Common Crawl CDX | none | every 28 days | free |

**Not built, as decided:** SerpApi (no node, no credential, no flag) and Gemini grounding. AI10 and W0's AIRW0-6 fail the build on either host.

### The chain

The chain lives in `ai_rank_requests_wiring.py`. It runs between `Load Link Prospects (Rank)` and `AI Rank Plan`. Every node has `onError: continueRegularOutput`, and each request node answers `[{ skip: true }]` when it has nothing to ask.

1. **`AI Rank Requests`** (`v5/code/AI_Rank_Requests.js`) is the planner. It reads stored data only. For each `on` site it decides what to read and what to reuse:
   - **Searches.** It uses the fan-out queries of the treated core questions (`ARD.fanoutOf` over the stored evidence and 28 days of answers), plus each question's own keyword, most frequent first.
     - If no question is treated yet, it uses the core questions. If there are none, it uses every stored AIR question. If there are none, it uses the active panel.
   - **Market.**
     - The site's own market, from `seo_sites`.
     - If that is missing, the dominant market of its questions.
     - If both are missing, it reads no results page. It never guesses a country.
   - **Budget.** `ai_rank_fanout_n` paid reads per ISO week, across both engines.
     - A Google reading of the last 7 days in the shared SERP cache costs $0.
     - So does a reading stored this week.
     - If the site asks Copilot, Google gets half the budget and Bing gets the rest.
   - **Reuse within the week and the month.** Three markers in `seo_cache` (kind `air`):
     - the week's marker `air:week:<site>:<yyyy-Www>` holds the reads made, the site's own result positions per search, and the compact Bing stats;
     - the month's LLM Mentions marker holds the pages and the metrics;
     - `air:cc:<site>` holds the Common Crawl reading.
     - A second run in the same week or month pays nothing.
   - **Ceiling.** At most $0.60 of planned paid reads per site per run.
2. **Six request nodes** share one source, `v5/code/AI_Rank_Calls.js`. The wiring bakes in which call each node is. Each has its IF and its HTTP node:

   | Node | What it calls | Retry |
   |---|---|---|
   | `AI Rank Mentions Call` | DataForSEO, paid | in-200 gate, no node retry |
   | `AI Rank Bing Call` | Bing Webmaster (`SEOcredBingWebm`) | retry rule |
   | `AI Rank SERP Call` | DataForSEO, paid | in-200 gate, no node retry |
   | `AI Rank CC Collections` | Common Crawl crawl list | retry rule |
   | `AI Rank CC Index Call` | Common Crawl index | retry rule |
   | `AI Rank Brave Call` | Brave (`SEOcredBraveApi1`, header `X-Subscription-Token`) | retry rule |

   - The SERP request node runs after the Bing stats. It reads Bing for a search only when Bing Webmaster gave no position for it.
   - A search, location and engine that two sites share is one request.
3. **`AI Rank Fetched`** (`v5/code/AI_Rank_Fetched.js`) emits one item per `on` site in the CONTRACTS §6 shape:
   - The required fields: `site_id, cost_usd, mentions_pages, target_metrics, bing_stats, serp_reads, cc_captures, brave`.
   - Additive fields: `engine` on each SERP read; `bing_stats.positions_basis / queries / pages / query_pages / crawl_stats / from`; `cc`; `reads`; `basis`; `errors`; `brave_usd_est`; `cost_basis`; `cache_rows`.
   - **Money.** `cost_usd` is DataForSEO only. It counts every task once by its id, across both calls and both attempts of the gate. A results page two sites share is paid by the first site.
   - **Brave** reports no cost per call, so its figure is `brave_usd_est`, an estimate, and is never put in `cost_usd`. The settle writes the measured figure into `dfs_usd`.
4. **`AI Rank Fetch Rows` → `Save AI Rank Fetch Cache`** upserts by key with exactly the `seo_cache` columns:
   - the Google readings (kind `serp`, with the site id, through `SC.rowFor`; Bing readings never go there, because the key has no engine);
   - the three `air:*` markers.

### What the data feeds

| Data | Reaches | How |
|---|---|---|
| Google fan-out reads | the S1 basis of the Google cells and Perplexity | New contract line **D24**: `AI Rank Plan` merges `serp_reads` (engine `google`) into the site's copy of its Google map before `ARD.diagnose`. This is one helper plus one argument in P4's file, recorded in CONTRACTS.md. Before it, the plan read only stored `serp:` rows, so this run's reads never reached the kit. |
| Bing positions | Copilot | through `bing_stats.positions`. A Webmaster position comes first. A Bing results page fills a search Webmaster has no position for; `0` means read but not in the results. `positions_basis` says which. |
| Brave results | Claude | `fetched.brave` → `index.brave` (P4 already read it) |
| Common Crawl count | parametric hint | `fetched.cc_captures` → `index.cc_captures` (P4 already read it) |
| LLM Mentions pages | the source graph | `fetched.mentions_pages` → `ARD.sources` (`from: 'llm_mentions'`). A page the answers already cite stays `answers`; a page no answer cites comes in as `llm_mentions`. |
| LLM Mentions metrics | month-on-month proof | `target_metrics` (for P6 / the memo) |

## 2. Safety (owner rule: nothing else may break)

- **Off:** nothing new runs. The golden test AIRG is unchanged.
- **Shadow: no outside call at all**, paid, keyed or free.
  - CONTRACTS §5 allowed free Bing stats and Common Crawl in shadow. P5 keeps them `on`-only, so the shadow golden (AP3: every outside request identical to the off run) stays exact.
  - The planner answers `skip` and `AI Rank Fetched` answers `skip`, so the plan's `fetched` is null in shadow, as before.
- **On with every flag off:**
  - Only the free Bing stats and Common Crawl run.
  - `cost_usd` is $0.
  - The settle's DataForSEO figure is the off run's (AI1).
- **Brave without the key:**
  - `BRAVE_ENABLED` (`env_settings.py`) is baked as `false` into the planner and the six request nodes, so no Brave request is ever made.
  - The node and its credential reference stay in the workflow, as the Bing and Ahrefs nodes do. n8n does not check credential references on import.
  - `sync_credentials.py` creates `SEOcredBraveApi1` only when the variable is set. A dry run prints `skip SEOcredBraveApi1 (empty in .env: SEO_BRAVE_API_KEY)` and never prints a value.
- **Retries:**
  - The paid DataForSEO calls sit in `G.in200_gate`. retry_lint's N3 rule strips the node retry from the call and its `(Retry)` copy.
  - The free and keyed calls carry `retry_lint.RETRY`.
  - The gate's own five nodes per call also fail closed (`onError` set by the wiring).

## 6. Owner steps

1. **Brave key.**
   - Create a key at https://api-dashboard.search.brave.com (Search plan, with its monthly free credit).
   - Put it in `n8n/.env` as `SEO_BRAVE_API_KEY=<key>`. The template line is in `n8n/.env.seo.example`. Never paste it in chat.
   - **Locally:** run `python3 seo-agent/apply_env.py`. It rebuilds with `BRAVE_ENABLED`, creates `SEOcredBraveApi1` through `sync_credentials.py`, imports and publishes.
   - **On production:** add the variable to the host's secret store and deploy the engine with the merge-main and node-diff rule. The credential goes through `sync_credentials.py --out`; see DEPLOY.md / RUNBOOK. This needs the owner's yes.
2. **Per site,** through Site Admin `monitors`:
   - `ai_rank_mode: 'on'` (after shadow looks right);
   - then, as wanted: `ai_rank_mentions: true`, `ai_rank_fanout_n: 20`, `ai_rank_brave: true`.
   - Bing results pages are read only for a site whose `ai_engines` include `copilot`. For any other site, Bing positions come from Bing Webmaster only.
3. **The live checks** of DESIGN 7.3 need the owner's yes. They confirm the fields marked "needs one live call" in §4:
   - one LLM Mentions read per site (≈ $0.50 for both sites);
   - 20 fan-out reads per site (≈ $0.08);
   - one Brave search after the key.
4. **Deploy order:** P5 adds no table and no column, so `sync_tables.py` has nothing new from P5. The new `seo_cache` keys (`air:week:*`, `air:cc:*`, `air:mentions:*`) need no migration.

## 7. Notes for the integration and the review

- **Files beyond the contract list.** `v5/code/AI_Rank_Calls.js` is new and P5-owned: one source for the six request nodes.
  - `AI_Rank_Plan.js` (P4's) gets the D24 helper only.
  - `CONTRACTS.md` gets the D24 line.
- **`build_v4.py` `_PAID_CREDS55`** (the R17 ledger-order check) does not list `SEOcredBraveApi1`. That file is not P5's, so this is left for integration.
  - The Brave node sits on the AIR branch after the reservation, so the order holds.
  - The check would still be stronger with Brave on the list.
- **Brave node retry.** retry_lint requires `RETRY` on non-DataForSEO nodes.
  - n8n re-sends every item of a multi-item node when its first item fails, so the worst case re-bills one run's ≤ 10 searches twice, which is ≤ $0.10.
  - A paid non-DataForSEO rule in retry_lint (its owner's call) would remove that.
- **Shadow is stricter than CONTRACTS §5** (no free reads in shadow). If the owner wants Bing stats and Common Crawl in shadow, AP3's "outside requests identical" check has to allow those two hosts first.
- **`ai_rank_reset.py` (P4)** does not clear the new `air:week:*` / `air:cc:*` / `air:mentions:*` rows. They are keyed by week or month, or refreshed every 28 days, so nothing goes stale. A purge could add them.
