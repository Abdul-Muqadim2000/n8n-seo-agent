## Engine-side needs (not done here; n8n/ untouched)

1. `seo_ai_visibility.compare_json` with the contract above (incl. `window`), the answer columns `named` / `cited` (URL) / `position`
   / `entities`, and the pulse columns `sample_mode` / `questions_asked` / `engines_answered` / `partial` - the app reads them when
   present and falls back otherwise. NOTE: if `cited` changes from a boolean to a URL, the engine's own consumers of the column must
   change with it; the app accepts both.
2. A3: the app mirrors AI_Plan.js's cut but cannot see the fit gate's run-time refusals. Best: the engine writes an "asked in the last
   run" / "queued" state per prompt row, and the app shows that instead of mirroring.
3. A2: the engine reserves its own calibrated `ai_visibility` estimate (`_cost_cal.js`), which is still the 8-question figure. The
   app's quote and the cost-sync cap now follow the panel; the engine's reservation / spend guard should use `AIP.cost(...).run.full`
   too, or the engine's guard and the app's quote disagree for big panels.
4. A9 matches ledger entries to runs by time window (`ref.mode` + domain). If the engine stored the run's execution ids on the
   `seo_ai_visibility` row (the state row in `seo_cache` has them), the charge could be matched exactly by `ref.engineRunId`.
5. A12 needs no engine change; owner decision still open (audit A12): whether measured history should be kept and shown under "before
   you verified" instead of deleted. The app now deletes it on a verified owner's site delete.
