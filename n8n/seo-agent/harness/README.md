# SEO Agent — offline test harness

Runs every Code node of the workflow in a real Node.js runtime against realistic fixtures
(DataForSEO, Jina Reader, PageSpeed, LLM outputs) **without calling any paid API**.

```bash
# from n8n/seo-agent/harness — uses the Node runtime inside the running n8n container
docker cp . n8n-n8n-1:/tmp/harness && docker exec -u root n8n-n8n-1 chown -R node:node /tmp/harness
docker exec n8n-n8n-1 sh -c 'cd /tmp/harness && CODE_DIR=/tmp/harness/code_v4 OUT_DIR=/tmp/harness/out node scenarios_v5.js'
docker cp n8n-n8n-1:/tmp/harness/out ./sample-output   # generated .doc reports (HTML) for eyeballing
```

* `harness.js` — mini n8n executor: mocks `$input`, `$('Node')`, `$runIndex`, `$getWorkflowStaticData`.
* `fixtures.js` — response shapes for every external call; edit to reproduce a customer's site.
* `scenarios_v5.js` — all five product modes + edge cases (blocked site, empty SERP, truncated LLM output, apex→www redirect).
* `fixtures_live/` — real DataForSEO responses captured on 2026-10-02 (LLM engines, AI Overview / AI Mode, LLM Mentions, Backlinks, Content Analysis, Business Data; no account data); `fixtures_monitors.js` builds the monitor fixtures from them (S19-S21).
* `accuracy/` — the labelled accuracy set (G18, S49): `findings.json` / `links.json` (a human label, a reason and a source per real case), `sites/*.json` (three sites captured with free public fetches), `score.js` (the scorer; also runnable on its own to print every finding with its label) and `capture.js` (run by hand to add a site, never by the harness). Doc: `../ACCURACY_SET.md`.
* Scenarios S0-S22 cover every mode, the trackers, the cadence, the E-E-A-T page types (S16-S18), the growth monitors (S19-S22) and the v4.6 reuse rules (editor gate, domain-age cache, rank deferral, trend / SERP reuse, monthly AI engines, quarterly link gap, change-aware audits): 514 node runs, 0 failed on 2026-10-02.

## PRC contract: the page-run context (page-quality programme 2026-10-29, PLAN §3.0 step 2, REVIEW_CODE H2)

What a content run hands on, so the final version (Page Finalize) can judge the page with the same facts the page run had. Example:
`fixtures/prc_example.json` (anonymised from production page run 3299).

**Gating fields** decide whether a page can be called Ready. Every stored content report already carries them, old reports included, so
the app derives them from the stored payload of the **original** report (`o.original`, never `o.base`) and `finalReportPayload` copies
them through to a second finalize. A missing gating field can never produce Ready.

| Field | Where it is in a stored content payload |
|---|---|
| `qa_blocking[]` | `payload.qa_blocking` (`{code, text, action}`) |
| `duplicate_targets[]` | `payload.meta.originality.duplicate_targets` (`{url, title, keyword_words_shared_pct}`) |
| `verdict` | `payload.verdict`, a string: `GO`, `GO_WITH_CHANGES`, `AVOID`, `NOT_CHECKED` |
| `score` | `payload.score` (the verdict score, 0-100 or null) |
| `score_withheld` | `payload.score_withheld` |
| `page_type` | `payload.meta.page_type` |
| `verdict_acknowledged` | new (W0-D): true only when the run was started with `hold_ack`; absent = false. PLAN writes it `verdict.acknowledged`, but `verdict` is a string, so it is its own field |

**Grading fields** make the grade comparable between the page run and the final version. W0-B adds them to *Build Webhook Response*;
no report delivered before that carries them, and `seo_content_log` holds none of them (no fallback). A missing grading field is advice
"not checked: <field>" and never blocks Ready.

| Field | Source in the page run |
|---|---|
| `length_band` | the final QA's `content_qa.length_band` |
| `coverage_target` | *Parse Brief* `coverage_target` |
| `terms[]` | *Parse Brief* `content_brief.terms_to_use` |
| `facts[]` | *Parse Brief* `facts` (claim, source, url, title) |
| `sources_cited[]` | the final QA's `content_qa.sources_cited` (anchor, url, host, tier) |
| `style_guide` | *Parse Brief* `style_guide` |
| `site_urls[]` | *Parse Brief* `site_urls` |
| `serp_shapes` | `KWI.serpPageTypes` on the results page (W0-C carries the top-10 list; the example uses the 6 pages 3299 read) |
| `regulatory_facts[]` | *Collect Regulatory Facts* (Fix 6, W0-F): `{date, obligation, subject, threshold, url, paragraph, source_tier, source_date, as_of, supersedes, status}`; the example entry is illustrative |
| `content_request_id` | the run's request id (3299 sent `content_request_id: ""`, a form run: fall back to `request_id`) |

`replay.js` replays recorded production node runs on the current generated code: `const R = require('./replay')(H); const fx =
R.load('replay_3299.json.gz'); const r = await R.replay(fx, 'Content QA', 2);` mocks exactly the node runs the code read in production
(by start time), runs the node on the recorded input and returns `{ out, first, recorded, recordedFirst }`. `opts.input` / `opts.mocks`
change a part (`null` removes a mock). Scenario `scenarios_replay.js` (RPL1-RPL4) checks the fixtures are anonymised, replays every run
and prints the BEFORE numbers Wave 0 changes.

* `fixtures/replay_3299.json.gz`: page run 3299 ("ms 365 erp", Service Page, verdict 42): Page Fix, Content QA, Originality Check and
  Page Candidates (3 rounds each), Blog Package, the nodes they read and the callback. On the code of 2026-10-29 every run reproduces
  production except today's date in the schema.
* `fixtures/replay_3336.json.gz`: the finalize of that page, with the app's request (old format) and the recorded Finalize Editor answer.
* `fixtures/ranking_guide_949.json`: the guide that ranks (exec 949, ladder rung 2, 319 impressions in its first week, one query at #12):
  the live page in the draft format, its brief, site model, critique and QA rounds, and its search outcome. Its verdict score is not
  stored in the repo: a hold rule must not depend on it.
* `fixtures/regulatory_pages.json` (W0-F, Fix 6): short passages of the UAE Ministry of Finance's own texts as the reader returns them
  (Ministerial Decision No. 244 of 2025 Article 5, its amendment No. 66 of 2026, the news item of 10 May 2026), with the line breaks a
  PDF keeps, plus synthetic secondary pages. Scenario `scenarios_w0f.js` (W0F1-W0F9): the regulatory kit (`code_v4/_regulatory_kit.js`,
  a shim written by build section 153), the plan on 3299's own Analyze Competitor Pages item, the amendment beating its original,
  passed / in-force status in the market's time zone, the two-source tier and "none could be confirmed", the paid fallback when SearXNG
  is down, Collect Facts carrying the facts on, Content QA's record (never a score change) and the 949 guide's guard.
* Anonymised for the public repo: brand Nova&, domain novaand.example (the domain label equals the brand, as on the real site, so brand
  detection behaves the same), the client's own page prose cut to lines of 10 words or fewer (headings and slogans stay), competitor page
  bodies removed, hook token, API key and company id replaced. Our generated drafts keep their text with the identity swapped.
